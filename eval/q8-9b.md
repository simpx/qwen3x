## 格式与数值

`make test` 中的 pack 测试用独立标量 reference 覆盖全零、正负 rounding 边界、随机
BF16 block、错误 config/schema 和截断 shard。`q8-cpu-test` 覆盖 CPU Q8 embed/dot/mv。

synthetic 9B 固定权重同时走 CUDA decode 和 batch prefill，二者与 NumPy reference 的
最大绝对误差均为 `7.6293945e-06`，两条 CUDA 路径逐元素一致。

真实 9B Q8_0 的 backend 对齐结果：

```text
1 token CPU/CUDA: max_abs_error=2.3603439e-05, mean_abs_error=5.1930570e-06
4 token CPU/CUDA: max_abs_error=1.3351440e-05, mean_abs_error=2.0934174e-06
top-10 and argmax: equal
```

官方 Transformers BF16 与 qwen3x Q8_0 在 token 0 logits 上：

```text
max_abs_error=0.52583945
mean_abs_error=0.06621085
argmax: 198 == 198
top-10 overlap: 9/10
4-step greedy: [0, 198, 0, 198, 0] == [0, 198, 0, 198, 0]
```

官方 reference 使用 `Qwen3_5ForCausalLM`，通过 427 项显式 key mapping 只加载 text model；
22 层放在 GPU，后 10 层、final norm 和 lm_head 由 Accelerate 放在 CPU。原始输出保存在
`build/9b-bf16-reference.txt` 和 `build/9b-bf16-greedy.txt`。

## 外部 Q8_0 基线

外部基线只用于区分模型行为和 qwen3x 实现问题；qwen3x 不读取 GGUF，也不依赖 llama.cpp
或 Unsloth。固定版本构建参数：

```sh
cmake -S build/llama.cpp-b10516 -B build/llama.cpp-b10516/build-cuda \
  -DGGML_CUDA=ON -DLLAMA_CURL=OFF -DLLAMA_BUILD_TESTS=OFF \
  -DLLAMA_BUILD_SERVER=ON -DCMAKE_BUILD_TYPE=Release \
  -DCUDAToolkit_ROOT=/usr/local/cuda \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc
cmake --build build/llama.cpp-b10516/build-cuda \
  --target llama-bench llama-simple llama-server -j4
```

`llama-simple -ngl 99 -n 32 'Respond with exactly: hello'` 输出 `hello`。相同的
Chat Completions 请求在 `--ctx-size 40960 --parallel 1 --reasoning off` server 上也严格返回
`hello`。

固定三次 benchmark：

```sh
llama-bench -m Qwen3.5-9B-Q8_0.gguf -p 4096 -n 32 \
  -ngl 99 -fa on -r 3 -o json

prompt 4096: 6708.275 +/- 6.365 tok/s
decode 32:     68.228 +/- 0.699 tok/s
```

相同 fixture、system prompt、temperature 0、thinking off 和每轮 1024-token 预算的 agent
结果保存在 `eval/results/agent/llama-b10516-unsloth-q8_0-1024/`：

```text
inspect: pass,  tool_error_count=0, 17.424 s
review:  fail,  tool_error_count=0,  3.836 s
bugfix:  pass,  tool_error_count=0,  5.775 s
```

`review` 找到了三个预设问题且未修改工作区，但答案写成 `safe_divide (line 6)`，没有给出
rubric 要求的 `utils.py:6` 文件位置，因此失败。这是模型回答精度差异，不是 tool-call parse、
HTTP 或 chat template 失败。相对地，qwen3x 的同一轮三个场景全部通过。
